## Implementation Steps

### Step 1: Sample Application (`app/`)
- Simple Express.js app with a health check endpoint (`GET /` returns "Hello from ECS!")
- Dockerfile (multi-stage: build + slim runtime)
- Lightweight — just enough to prove the pipeline works

### Step 2: Terraform Infrastructure (`terraform/`)
- **VPC**: 2 public subnets across 2 AZs (ECS Fargate needs multi-AZ)
- **ECR**: Private container registry to store Docker images
- **ECS Fargate**: Cluster + task definition + service (serverless, no EC2 to manage)
- **ALB**: Load balancer in front of ECS tasks with health checks
- **Security Groups**: ALB allows port 80 inbound; ECS tasks allow traffic only from ALB
- **IAM**: Task execution role for pulling images from ECR

### Step 3: GitHub Actions — Terraform CI/CD (`.github/workflows/terraform.yml`)
- **Trigger**: On PR to `main` → runs `fmt check`, `validate`, `plan`
- **Trigger**: On push to `main` → runs `apply`
- Uses `hashicorp/setup-terraform` action
- AWS credentials via GitHub Secrets (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`)
- Stores plan output as PR comment for review

### Step 4: GitHub Actions — Docker Build & Deploy (`.github/workflows/deploy.yml`)
- **Trigger**: On push to `main` (after Terraform workflow, or changes in `app/`)
- Steps:
  1. Checkout code
  2. Configure AWS credentials
  3. Login to ECR
  4. Build Docker image, tag with `latest` + git SHA
  5. Push to ECR
  6. Update ECS service (force new deployment to pull latest image)
- Uses `aws-actions/amazon-ecr-login` and `aws-actions/configure-aws-credentials`

### Step 5: Documentation
- A `README.md` with:
  - Prerequisites (AWS account, GitHub repo, Terraform CLI)
  - How to set up GitHub Secrets
  - How to run Terraform locally first
  - How the pipeline works end-to-end

## Choices Made (keeping it simple for learning)

- **Fargate** over EC2 launch type — less infra to manage, focuses learning on CI/CD not server ops
- **ECR** over Docker Hub — native AWS integration, no extra credentials
- **Single environment (dev)** — avoids complexity; you can add staging/prod later
- **Public subnets for ECS** — simpler networking (no NAT gateway cost); production would use private subnets
